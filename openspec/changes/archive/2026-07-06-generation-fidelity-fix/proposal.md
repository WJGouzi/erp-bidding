# 生成保真修复 — Proposal

## Why

当前标书生成结果存在 6 个保真度问题，导致生成的标书与招标文件原文要求之间存在系统性偏差。这些问题根因不在解析侧（解析已基本正确），而在**生成侧的数据传递和内容组装逻辑**。

### 问题总览

| # | 问题 | 违反的 AGENTS.md | 影响 |
|---|------|-----------------|------|
| 1 | 目录含"评分响应"、"供应商须知"等多余章节 | 1.2（不能使用同一模板）、2.4（章节顺序） | 标书结构与招标文件不符 |
| 2 | "待人工补齐清单"独立成板块，含 [PENDING]/JSON | 1.1（严格遵守招标文件） | 暴露调试信息，交付物不专业 |
| 3 | 资格性文件被 LLM 扩写 | 2.1（模板原样复制）、1.4（禁止 LLM 推导） | 模板内容被改写，有废标风险 |
| 4 | 封面未使用招标文件样式 | 6（封面样式） | 封面格式不符 |
| 5 | 表格解析正确但未落入 docx | 3（表格识别与处理）、2.1（混合排版保真） | 表格丢失或变成段落 |
| 6 | 已有内容区域被 LLM 修改/美化 | 1.4（禁止 LLM 推导） | 原文被篡改 |

### 根因

当前生成管线架构为"分析+综合"模式：

```
招标文件 → 解析为 analysis_data → 目录合并(多源) → LLM综合生成 → docx组装
```

这个模式有三层问题：

1. **目录多源合并**：目录引擎同时从格式要求、check_items、评分匹配、LLM 推断、模板库等多个来源合并，导致招入原文未要求的章节
2. **内容生成无约束**：所有章节统一走 LLM 生成流程，系统不知道哪些章节有原文模板、哪些没有，导致模板被改写
3. **数据传递断桥**：解析侧正确识别了表格结构和混合排版，但生成侧只传递文本，表格信息在传递过程中丢失

## What

针对 6 个问题，分别改造：

1. **目录净化**：目录唯一源改为招标文件的 required_sections，剔除推断章节
2. **缺失归位**：删除独立"待人工补齐清单"板块，缺失项归位到所属章节
3. **模板锁定与两阶段生成**：检测到模板→锁定原文→仅填空位；无模板才 LLM 生成
4. **封面修复**：优先使用招标文件封面模板
5. **表格桥梁+混合排版**：传递结构化 content_blocks，按序写入 docx
6. **内容状态检测**：填充前检测原文状态，已有内容锁定

## How

分三个批次交付：

- **批次 1（P0 🔴）**：目录净化 + 模板锁定 + 两阶段生成 — 修复核心保真问题
- **批次 2（P1 🟡）**：缺失归位 + 封面修复 + 表格桥梁 — 完善交付质量
- **批次 3（P2 🟢）**：内容状态检测 + 测试 — 安全网和验证
