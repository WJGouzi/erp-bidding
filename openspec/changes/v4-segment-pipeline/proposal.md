# v4-segment-pipeline

## 问题

当前标书生成流程存在以下质量问题：

1. **目录生成是模板套用而非分析驱动** — 不论招标文件的实际结构如何，系统都强制套用10章硬编码骨架，无法反映每份招标文件独有的"投标文件组成"要求
2. **缺少强制条款识别** — 系统无法区分"必须原文复制"的内容（声明函、承诺书）和"可自由撰写"的内容（技术方案），导致 LLM 可能改写不可改写的内容
3. **解析结果不可追溯** — analysis_data 中的每个提取项不记录原文位置（哪一章哪一页），无法验证"忠实原文"
4. **无置信度体系** — 知识库检索的分数在传递过程中丢失，生成阶段无法判断"这段材料可信度如何"
5. **废标条件未被有效利用** — 废标条件被提取后不参与生成决策，没有转换为生成约束

## 方案

采用"分段解析 + 分析驱动目录 + 三路生成引擎"的新架构。

核心变更：
- **分段解析**：按招标文件的章节结构逐段独立分析，LLM 组装为综合JSON
- **目录驱动**：从招标文件的"投标文件组成"章节提取目录骨架，无显式格式时从分析数据推断
- **三路生成**：HARD（填空）+ SOFT（匹配）+ FREE（约束LLM），按内容类型路由
- **置信度贯穿**：召回分数保留到生成层，在 docx 中可视化
- **废标→约束**：废标条件转换为生成约束（guardrails），不进prompt

## 阶段规划

| 阶段 | 内容 | 文件 |
|------|------|------|
| A | 强制条款识别器 + 置信度传递 | mandate_classifier.py, helpers.py 改动 |
| B | 目录生成改造 | catalog_skeleton_extractor.py, catalog_inference.py, catalog.py 改造 |
| C | 分段解析 + LLM 组装器 | assembler.py, analysis_v3/__init__.py 改造 |
| D | 分段生成引擎 + docx 渲染 | helpers.py 三路路由 + docx 渲染 |
