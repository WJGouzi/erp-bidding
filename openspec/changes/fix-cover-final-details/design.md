## Context

标书封面渲染有两个代码路径：
- **Pre-loop**（~3900行）：渲染 outline 中第一个 `is_cover=True` 的封面（含"正本"+内容）
- **Main loop**（~4490行）：渲染后续封面（当前缺"正本"）

当前问题：
1. 正本 `tblpY=1400000`（3.89cm）过大，实际需改为 406400（≈1.13cm，约两行高度）
2. 第二封面没有"正本"浮动表格
3. `page_margins` 数据从 parser 捕获到 analysis 注入，但渲染端从未使用，属于死代码
4. 两封面 LLM 填充逻辑一致，但第二封面代码路径缺少"正本"

## Goals / Non-Goals

**Goals:**
- 正本到页顶部距离改为约两行（tblpY=406400）
- 第二封面增加正本渲染（与第一封面完全一致）
- 删除 page_margins 相关死代码
- 两封面渲染逻辑统一

**Non-Goals:**
- 不改动封面内容字段的 LLM 填充逻辑本身（仅确保第二封面也使用相同逻辑）
- 不改动封面模板识别逻辑（`is_cover` 标记已在 catalog.py 中完成）

## Decisions

### 1. tblpY 值选用 406400 EMU

406400 EMU = 16pt × 12700 EMU/pt × 2 行（单行距）。
用户明确要求"离页面的顶部，往下两行"，且是两封面统一使用。

### 2. 第二封面正本 = 复制第一封面正本代码

将第一封面 pre-loop 中的"正本"浮动表格代码段完整复制到第二封面的渲染开始位置（page_break 之后，title 之前），使用完全相同的 tblpX/tblpY。

### 3. page_margins 直接删除

无需替换方案，因为：
- 数据从未在渲染端被消费
- 封面边距应保持与招标文件一致，但当前没有渲染端消费该数据
- 删除可减少代码复杂度和数据体积

## Risks / Trade-offs

- [低] 删除 page_margins 后，如果未来渲染端需要边距信息，需重新添加
- [低] 第二封面复制"正本"代码块会产生少量重复代码，但逻辑清晰且两封面独立
